# Coding-Kontext – MAF-Training

- Python 3.12; `agent-framework==1.19.0`, `agent-framework-foundry==1.13.1` aus `pyproject.toml` / `uv.lock`. Import `agent_framework`, `Agent` und `tool` aus `agent_framework`, `FoundryChatClient` aus `agent_framework.foundry`.
- Aktuelle API: `Agent(client=…, tools=[…])`, `await agent.run(…)`; Tools mit `@tool` und beschriebenen Parametern; Session `AgentSession`/`create_session()`. `.env` explizit mit `load_dotenv()` laden. Entra-Login lokal über `AzureCliCredential`, kein Key im Repo.
- Nicht verwenden: `ChatAgent`, `AgentThread`, `@ai_function`, `run_stream()`, `AzureAIAgentsProvider`, `agent-framework-azure-ai` (entfernt seit Python 1.0). Der offizielle alte `agent-framework-azure-ai-py`-Skill enthält diese APIs; nicht unbesehen übernehmen.
- **Fresh information first:** vor API-Änderungen installierte Signaturen (`uv run python -c 'import inspect; ...'`) und aktuelle Microsoft-Doku prüfen: [2026-Änderungen](https://learn.microsoft.com/en-us/agent-framework/support/upgrade/python-2026-significant-changes), [Foundry-Provider](https://learn.microsoft.com/en-us/agent-framework/integrations/by-component/model-providers/microsoft-foundry). Nicht verschiedene Release-Stände mischen.
- Synthetische Trainingsdaten bleiben lokal; R-03-Versionen numerisch segmentweise vergleichen, nicht als Text/Float. Fehlende Angabe = „unklar“; Widerspruch = „unklar“; Fundstellen nur aus der passenden Dokumentversion. Übungstests (Marker `exercise`) sind absichtlich übersprungen und werden bei Umsetzung aktiviert. Kein scheinbar grüner Fachtest ohne Assertions.
- Prüfworkflow: Das LLM extrahiert nur (`pruefung.Extraktion`), Bewertung passiert in `pruefung.vergleiche`. Keine Regeln in Prompts verschieben. Ob eine Fundstelle den Gegenstand der Anforderung betrifft, prüft `pruefung.fremder_gegenstand` anhand von `anwendbarkeit` im Katalog (z. B. §6.3 Raumtemperatur ist kein Beleg für R-05). Executor-IDs, Workflow-Name und Nachrichtentypen in `pruefworkflow.py` nicht umbenennen, sonst lassen sich vorhandene Checkpoints nicht mehr laden; neue Nachrichtentypen in `CHECKPOINT_TYPEN` aufnehmen. `referenz/*.angaben.json` nie an Testergebnisse anpassen.
